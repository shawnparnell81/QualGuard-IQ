# Extension licence signing keys: custody, generation and rotation

Shawn Parnell, as publisher, holds the production licence signing private key. It is an explicit deployment input that
needs an authorized human decision. No production key exists in this repository, in configuration, in the database, in
logs or in the user interface, and none was generated by the build.

## What an installation holds

Public keys only:

- `Licensing:PublicKeyPem`: the original single key (shown as key id `config-legacy`). It verifies QGL1 licences.
- Keys registered under Platform › Marketplace › License verification keys, each with a key id, the ES256 algorithm
  (ECDSA P-256 with SHA-256), an environment (Production or Development), a fingerprint (SHA-256 of the public key) and a
  status: Active, Retired or Revoked. A private key pasted there is refused. Every change is audited.
- `Licensing:DeploymentId` and `Licensing:CustomerId` (optional) scope licences to this installation.
- `Licensing:AcceptDevelopmentKeys` (default false). Leave it false on production. With false, development keys cannot be
  registered and licences signed with them are refused.

## Licence format

`QGL2.<header>.<payload>.<signature>`. The header carries the key id and algorithm, so several keys can be valid during a
rotation. The payload holds the licence id, licensee, extensions (package keys or `*`), issue and expiry dates, an optional
customer id, an optional deployment list and the key environment. Activation checks the signature, the key's status and
environment, expiry, extension scope, customer and deployment scope, and the revocation list. QGL1 licences still activate
against active production keys.

## Production key generation (offline, by the publisher)

1. Use an offline machine that is not a build or deployment server. Generate the key there:
   `openssl ecparam -name prime256v1 -genkey -noout | openssl pkcs8 -topk8 -nocrypt -out pub-2026-a.private.pem`
   then `chmod 600 pub-2026-a.private.pem`. Choose a key id that does not start with `dev-`.
2. Export the public key: `openssl ec -in pub-2026-a.private.pem -pubout -out pub-2026-a.public.pem`.
3. Keep the private key on encrypted removable media or in a hardware token or offline password vault, with a sealed
   backup copy in a second location. Record who holds it and where. Never email it, commit it or paste it into a ticket.
4. Give installations the public key and key id only. They register it with environment Production, or set it as
   `Licensing:PublicKeyPem` on a new installation.

## Issuing a licence (offline)

On the offline machine, run the licence command with the key behind a secret reference. The reference is never the key
itself:

```
Licensing__Signing__KeyId=pub-2026-a \
Licensing__Signing__PrivateKeyRef=file:/media/keys/pub-2026-a.private.pem \
dotnet QualGuardIQ.Api.dll license issue --license-id L-2026-0001 --licensee "Acme Aerospace" \
  --extensions aerospace-as9100 --expires 2027-12-31 [--customer ACME] [--deployments acme-plant-1]
```

`env:NAME` is also accepted as a reference. The command refuses to run when no production key is configured, when a
`dev-` key id is used for production, when the reference is an inline key, when the key file can be read by other users,
or when the reference holds only a public key. It prints the licence key and nothing else.
`license public-key` prints the configured key's public key and fingerprint.

## Development keys

`dotnet QualGuardIQ.Api.dll license dev-keygen --out /tmp/qgiq-dev-keys` creates a `dev-…` key pair for test
installations. It refuses to write inside a git working tree, writes the private key owner-only, and names it
`*.DEVELOPMENT-ONLY.private.pem`. The `.gitignore` excludes `*.private.pem`. Production installations refuse licences
signed with development keys.

## Rotation and revocation

- **Rotate:** generate a new key, register it on every installation, start issuing with it, then retire the old key.
  Licences already activated under a retired key stay valid until they expire. New activations need the current key.
- **Compromised key:** revoke it on every installation. Every licence it signed stops counting at once. Reissue the
  affected licences with a new key.
- **Revoke a licence:** revoke it on the installation, or enter the licence id from a publisher revocation notice under
  "Revoke a license id". That also blocks a licence that was never activated there.

## Publisher licence tool (`tools/QualGuardIQ.LicenseTool`)

A stand-alone command line tool, `qglicence`, for the publisher's own computer (Windows, macOS or Linux, .NET 10 SDK):

- `keygen --key-id ID --private-out FILE --public-out FILE` creates an ES256 key pair. It refuses to write inside a git
  working tree, never overwrites an existing key, never prints the private key and writes it owner-only on Linux/macOS.
- `issue --key FILE --key-id ID --licence-id ID --company NAME --expires yyyy-MM-dd [--tier T] [--users N] [--max-sites N]
  [--sites a,b] [--extensions a,b|*] [--customer ID] [--deployments x,y] [--out FILE]` signs a QGL2 licence. Extensions
  default to `*`. The licence is valid to 23:59:59 UTC on the expiry date.
- `verify --licence FILE --public-key FILE [--customer ID] [--deployment ID]` runs the same checks the application runs.
- `public-key --key FILE` prints the public key and fingerprint.

Add `--development` (and a `dev-` key id) for test keys. The payload now also carries optional `tier`, `maxUsers`,
`maxSites` and `sites`; licences without them still verify.

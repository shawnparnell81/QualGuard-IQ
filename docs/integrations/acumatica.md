# Acumatica connector research (contract-based REST)

- Auth: OAuth 2.0/OIDC. Register the client in **Connected Applications (SM303010)**, pick the flow (Authorization Code, Implicit, Resource Owner Password Credentials, Hybrid), add a shared secret, and request scope `api` (+`offline_access` for refresh). HTTPS is required. https://beacon.acumatica.com/r/Form-Reference-Guide/Integration-Forms/Connected-Applications, https://help.acumatica.com/Wiki/ShowWiki.aspx?PageID=c6294b6b-a460-491e-8130-ae55d063c15c&wikiname=HelpRoot_Dev_Integration
- **Gotcha:** there's no client-credentials grant in the flow list, so server-to-server uses Resource Owner Password with a dedicated integration user (restricted roles). Token: `POST https://<host>/<instance>/identity/connect/token`. https://help.acumatica.com/Wiki/ShowWiki.aspx?pageid=638b2743-8ca8-49a8-96d5-e2f0601b0827. The contract-based REST sign-in method also exists and, like OAuth, opens an API session that counts toward the license (https://beacon.acumatica.com/r/Integration-Development-Guide/Limiting-Connections-of-Integrated-Applications/License-Restrictions-for-API-Sessions-and-Requests). The exact path `/entity/auth/login` is **UNVERIFIED** (named on the "Sign In to the Service" page, not fetched).
- Connected apps must be added to a customization project to move to other instances (same general info page).
- Base: `https://<host>/<instance>/entity/Default/<version>/<Entity>`, e.g. `/entity/Default/25.200.001/SalesOrder/SO/000001`, header `Authorization: Bearer`. https://help.acumatica.com/(W(8))/Wiki/ShowWiki.aspx?pageid=ed9fe5ab-b3c0-444c-8335-ff3b0c8392d6
- Entities:
  - Manufacturing data uses the **MANUFACTURING** endpoint, e.g. `GET /entity/MANUFACTURING/25.100.001/BillOfMaterial/BOM000001/A?$expand=Operations,Operations/Material,Operations/Steps`. The key is BOM id + **revision**. Operations carry `OperationNbr` and `WorkCenter`. https://help.acumatica.com/(W(24))/Wiki/ShowWiki.aspx?pageid=981a9fe7-82b9-4667-ae8f-b0ed72fe2ed6, https://beacon.acumatica.com/r/Integration-Development-Guide/REST-API-Examples/BillOfMaterial/Create-a-Bill-of-Material?contentId=BVx2uCUtkpqsFYdN3YhtgQ
  - `StockItem` on the Default endpoint is confirmed in the $filter examples (https://help.acumatica.com/(W(28))/Wiki/Show.aspx?pageid=775ca16b-cba6-4c1d-89d5-c1df7833bfea).
  - `Customer`, `Vendor`, `Employee`, `PurchaseOrder`, `PurchaseReceipt`, `ProductionOrder` and the lot/serial inquiry, plus their exact field lists: **UNVERIFIED**. The per-version swagger.json is served only by a running instance (`/entity/Default/<ver>/swagger.json`), so it needs a customer or trial tenant.
- Paging/filter: `$top`/`$skip` (`$skip` applies first), `$filter` (e.g. `LastModifiedDateTime gt datetimeoffset'2025-10-17T00:00:00.000'`), `$expand` (Contract v4 requires every detail entity to be expanded), `$custom` for non-contract fields. https://beacon.acumatica.com/r/Integration-Development-Guide/REST-API-Examples/Parameters-for-Retrieving-Records/filter-Parameter, https://help-2024r2.acumatica.com/(W(2))/Wiki/ShowWiki.aspx?pageid=be37b0cb-eb17-41c0-944c-d52f7a65cf2e, https://beacon.acumatica.com/r/Integration-Development-Guide/REST-API-Examples/Parameters-for-Retrieving-Records/expand-Parameter, https://help.acumatica.com/Wiki/Show.aspx?pageid=a0444120-2e5d-41cd-8c65-0385210b0f8a
- Limits: each license sets max **API sessions**, **concurrent requests** and **requests per minute** (License Monitoring Console SM604000). A trial license allows 2 sessions and no other limits.
  - OAuth and REST sign-in both open an API session, and sessions that are never signed out block other apps.
  - Requests queue when the cores are busy. Once requests in the past minute reach 50% of the per-minute limit, each request is delayed.
  - A request is declined if the queue holds more than 20 or it waits more than 10 minutes.
  - Monitor on System Monitor SM201530.
  - https://beacon.acumatica.com/r/Integration-Development-Guide/Limiting-Connections-of-Integrated-Applications/License-Restrictions-for-API-Sessions-and-Requests
  - Design: reuse one token or session per connection, run requests one at a time by default, and always sign out cookie sessions.
- Events: **Push Notifications (SM302000)** send JSON POSTs from GI or built-in queries to a destination URL, with retries. https://beacon.acumatica.com/r/Integration-Development-Guide/Configuring-Push-Notifications-for-Real-Time-Monitoring/Push-Notifications-General-Information, https://beacon.acumatica.com/r/Integration-Development-Guide/Configuring-Push-Notifications-for-Real-Time-Monitoring/Push-Notifications-Destinations
- Errors: JSON with `message`, `exceptionMessage`, plus per-field `error` on entity payload (**UNVERIFIED**).
- Sandbox: customer sandbox tenants via partner/SaaS (**UNVERIFIED**). Writes: read-only default.
